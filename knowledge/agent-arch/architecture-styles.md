# Architecture Styles (Foundations)

Per-axis core principles for choosing and shaping the base structure of an agent-legible codebase. Distilled from axes 01-06 of the agent-architecture guide.

## When to use which (quick orientation)
- **Modular monolith is the default** for most products. Cheap ACID, in-process ordered events, one atomic artifact, a greppable call graph. It is the correct end state, not a way-station to microservices.
- **Topology (mono vs poly) is a second-order decision** downstream of two substrate properties. A HEAD-fresh server-side dependency graph (query plane) and a host-enforced trust root the agent's token cannot write. Lacking either → default polyrepo. Partition by measured fan-in, not trust tier.
- **Vertical-slice.** Use pure slices when the domain is use-case-shaped and invariant-poor (CRUD, glue, reporting, BFFs); over a shared domain spine when invariant-rich (money, tenancy, authz, PII).
- **Hexagonal.** Earns its keep only at a seam with proven multiple-impl variance or a closed-enum uncrossable boundary; pure ceremony everywhere else.
- **Event-driven.** Default synchronous+transactional; async must be earned per-edge (temporal decoupling / open-ended fan-out / measured throughput / durable-log-as-product).
- **Serverless/FaaS.** Unanimous "don't by default", modular monolith for steady CRUD; lambdalith as the middle; fine-grained FaaS only for natively event-shaped + bursty/idle workloads.

## Axis 01. Modular Monolith + Agent-Native Conventions
**Core principles**
- Gate what is expensive when it breaks, not what is cheap to check. A green check must mean something about blast radius and reversibility, or it is a sedative.
- Direction is the load-bearing wall; acyclicity is decoration. Each module declares an empty-by-default dependency allowlist; additions reviewed.
- The database is the one genuinely shared mutable thing, so make it a physical boundary (per-module schema + role + revoked grants). Schema is the one global concern. ONE ordered migration stream.
- Derivable facts are generated and forbidden from hand-editing; non-derivable facts (purpose, invariants) are backed by named tests or fenced UNVERIFIED. Reject "freshness" gates that fire on "code changed but doc didn't."
- The agent's primary entrypoint is a generated query surface (`manifest.json`), not prose. Conserve the window by minimizing high-yield retrievals, not bytes/file; a miss is a hard "does not exist."
- The unit of dangerous change is the cross-module FLOW, not the folder. Spend legibility budget on generated flow/blast-radius artifacts.
- Tier all paths by blast radius and bind agent permission to the tier. A control the actor can rewrite is not a control.
- Lean into monolith strengths (ACID, in-order in-process events, one atomic artifact); stop selling "clean extraction."

**Conventions & guardrails**
- `AGENTS.md` is a ROUTER (read-order, tier rules, STOP conditions like "if changing `api/` or `*.events.ts`, load the flow doc FIRST"). Module list lives in `manifest.json`.
- Per-module `AGENTS.md` = three zones. ≤400-token hand-written PURPOSE; CI-overwritten GENERATED block (API/deps/events); generated INVARIANTS block from `@invariant('...')` annotations on defending tests.
- Resolve symbols via `manifest.json` first (O(1) → file + signature + module); a miss means it does not exist. Search, don't fabricate. CI fails on any referenced path that doesn't resolve.
- Progressive disclosure as a 3-tier contract. TIER-0 (~500 tokens: purpose + signatures + STOP + linked flows); TIER-1 (internals: invariants + defending-test paths); TIER-2 (api/events: flow docs + consumer/blast map).
- Module declares an archetype (crud | rich-domain | integration | reporting); layers present-only-if-used; no empty stub folders. "One cohesive export cluster per file," not one export per file.
- Dependency DIRECTION via empty-default allowlist + must-fail/must-pass fixtures across two oracles; afferent/efferent coupling printed per PR with a committed ceiling.
- DB as physical boundary. Per-module schema + role, revoked cross-schema grants; CI rejects migrations referencing another schema or cross-schema FKs. One global ordered stream + a `migrate:check` reversibility proof; reject unguarded `DROP`.
- Event bus as compiled, versioned, registered surface. Single discriminated union both sides import, schema snapshot per payload, consumer-driven contract tests, orphan detector both directions, expand/contract only.
- Tiered blast-radius permission gate from `BLAST_RADIUS.yaml` (tier-0 edit freely, tier-1 human gate, tier-2 irreversible = propose-only; the file includes itself at tier-2). Block `--no-verify` server-side; agent may not edit guardrail configs without tier-2 approval.
- Mutation testing on boundary paths (replaces line coverage as the safety signal); ON+OFF flag-path assertions. Supply chain, i.e. committed lockfiles, OSV/audit required status, new top-level dep needs CODEOWNERS approval. Brownfield, i.e. every exception carries `TODO(ticket)` + expiry; total violation count monotonic-decreasing.
- Context strategy. Optimize retrieval legibility (one cheap high-yield hop), not static legibility. Per-module CI context-budget metric, soft-cap ~8k tokens = signal to split. Cap hand-written prose ~400 tokens.

**Antipatterns**
- Trusting the import graph as the dependency graph (blind to SQL, events, barrel re-exports). Acyclicity theater. The "freshness"/touched-with gate. Verified-block contamination (generated list lending credibility to a hand-written lie). Schema ownership by naming convention; offering both global and per-module migrations. Selling "clean extraction." One-export-per-file; mandatory 5-layer skeleton; line coverage as safety. Uniform write-access to a non-uniform-risk repo; a guardrail layer the agent can rewrite. Maximizing gates (a non-load-bearing gate is negative).

## Axis 02. Repo Topology: Monorepo vs Polyrepo
**Decision framework (IF/THEN)**
- IF a symbol's inbound fan-in exceeds the tier-0 threshold (e.g. >8 internal consumers, computed nightly) THEN it + its top consumers live in the monorepo core island.
- IF a service is a leaf (0-1 internal consumers) with independent deploy cadence THEN it stays a polyrepo behind a versioned, contract-tested boundary.
- IF you cannot stand up a HEAD-fresh full-tree graph queryable server-side THEN do NOT choose monorepo. Default polyrepo and build the index first.
- IF you cannot host-enforce the trust root THEN polyrepo's host-enforced repo walls are the safer default.
- IF hard regulatory/permission isolation per service is required (PCI, data-residency) THEN polyrepo per isolated domain is mandatory regardless of fan-in.
- IF measured agent PRs spanning >1 service are rare (<5%) THEN bias toward polyrepo leaves even for moderately-shared libs.
- IF a change touches a `@public-api` symbol / `packages/public-contracts` THEN switch to the publish protocol (semver + changeset + shim) regardless of where consumers live.
- IF a change touches migrations / proto / graphql / serialization / persisted cache keys THEN it is forward-only. Hard renames forbidden, expand/migrate/contract mandatory, `git revert` banned as remediation, in BOTH topologies.
- IF a lib's fan-in crosses the threshold over successive nightly runs THEN flag it to migrate into the island; the boundary is a measured, moving fact, not a religious choice.

**Core principles**
- Agent confidence is uncorrelated with agent coverage. Every tool (rg, nx affected, bazel query, registry dependents, lockfile, git revert) returns a confident, bounded, lossy projection. The job is to make each projection's boundary legible, not to pick the one that lies least.
- Decouple the QUERY plane from the EDIT plane. Edit in a bounded slice; route all completeness questions to a server-side full-tree index. Local rg/nx-affected over a partial tree is advisory-only.
- The trust root must be unreachable by the agent's principal. A boundary the controlled actor can edit is a suggestion with a changelog.
- Partition by the measured graph fact (fan-in), not the human-political fact (trust tier); the trust seam is invisible at the edit site.
- Atomic-in-source ≠ atomic-in-production. The monorepo escapes skew only for in-process type references.
- An agent fleet has no social backpressure, so engineer every shared serialization point and soft fence against pile-on.

**Conventions & guardrails**
- Dual-signal discovery for any rename/contract change. Run BOTH the typed reverse-dep query AND a raw lexical sweep across non-source (`*.json/*.proto/*.graphql/*.sql/migrations/`); any lexical hit not in the typed set is a suspected wire/dynamic edge. Divergence is the alarm.
- Three-part stopping rule. Typed-graph deps fixed AND string-grep reconciled AND consumer-driven contract tests green. Never graph-deps-alone.
- Version-in-play answered only by structured query JSON (`pnpm why --json`, `bazel query somepath`), never by reading a lockfile; "what runs in prod" from the deploy artifact/SBOM, never HEAD.
- Sparse/partial-clone state is a first-class hazard reported every task (like detached HEAD); expand the cone to the index-returned affected set before any cross-cutting commit. (Sparse-checkout is strictly worse than polyrepo invisibility; it presents incomplete as complete.)
- Host-enforced trust root. CODEOWNERS/branch-protection/BUILD-visibility/allowlists behind server-side push rulesets owned by a principal no agent token holds; a PR editing a boundary file in the same diff as the code it unblocks is auto-rejected.
- Path-scoped (not repo-scoped) write boundaries; per-task short-lived OIDC tokens; read-only remote-cache token for the fleet (only post-merge trunk CI writes); merge-queue throughput budget + circuit breaker freezing agent PRs in a red area; bot identities excluded from required-reviewer sets.
- Public contracts live in a physically separate, separately-versioned package the agent cannot edit with its task token. The boundary is a compile/permission failure, not a remembered annotation. Leaves expose identical `make build|test|lint` + machine-readable `.tool-versions`.

**Antipatterns**
- Comparing an equipped monorepo against an unequipped polyrepo. Sparse-checkout presenting partial as whole. Treating atomic-in-source as a contract/rollback guarantee. The hybrid's versioned boundary as an annotation rather than a compile/permission failure. Remote-cache poisoning (fast and wrong). Repo-spanning god-tokens.

## Axis 03. Vertical-Slice / Feature-Sliced Architecture
**Use it / don't.** USE pure vertical slices when the domain is use-case-shaped and invariant-poor (CRUD, integration/glue, reporting, BFFs, workflow-light tools). DO NOT cut the domain per slice when invariant-rich (money movement, tax/proration, tenant isolation, authz, PII, regulated workflows); a per-slice copy of a rule is a latent N-way incident the locality actively hides.

**Core principles**
- Duplicate SHAPE, share TRUTH. Rule-of-three governs only incidental glue. It NEVER governs a business invariant. An invariant is born in the spine with exactly one implementation on day one, so there is no clone to detect.
- Invariant-vs-coincidence is a lookup, not a guess. A stateless agent can't run Gate-1 from code. "Invariant" is a declared human-owned fact in `INVARIANTS.md`. On the list ⇒ inlining forbidden; off ⇒ duplicated by default; uncertain ⇒ surface the fork to a human.
- The working set is the computed closure, not the folder. Retire "one slice = one context window." closure(slice) = slice files + referenced spine symbols + event pub/sub peers + command callees' contracts + duplication-cohort + declared controls.
- Anything the agent is told to trust must be generated from code, hash-pinned to source, and honest about coverage. A confidently-wrong map is worse than no map. Generate-or-delete; only hand-authored survivors are `INVARIANTS.md` and the one-line "what this slice is for."
- Security/authz is a positive obligation at the trust-root seam, not a clone, not domain-kernel code. The worst failure is a missing control (zero clone signature). Trust-root is the only path to data, fail-closed, principal+scope on every call, own CODEOWNERS.
- Blast-tier is harness-owned, computed from the edge closure, can only ratchet up; the tier in a slice card is display-only. If computed > declared, declared is ignored and CI fails (letting the agent set its own tier is privilege self-assignment).

**Conventions & guardrails**
- First question is "invariant or control?", not "which folder?" Lookup against `INVARIANTS.md`/control edges before opening the slice; if tagged, worklist = every slice carrying that tag (O(N) scatter → O(1) lookup).
- Push the cohort at edit time; never rely on the agent to query. Harness injects "this block has N siblings at <paths>" the moment the agent touches dup-cohort code. Passive indexes get skipped.
- Invariant-governed values are never computed in slice code. The mapper formats; the value comes from a spine domain-object call. Arch-fitness rule fails CI on any invariant-tagged field assignment not originating from a spine call.
- Use the scaffolder, never `cp -r`. `new-slice --query` emits the minimal archetype; verbs from a controlled allowlist; command-vs-query derived from a verifiable fact (does the handler open a write txn).
- On an ambiguous router match or new-vs-edit fork, STOP and surface it (a wrong-slice silent no-op deploy is worse than a clarifying question). Trust the map only when its `srcHash` matches source; if stale, degrade LOUDLY to source-read cost.
- ONE generated edge store (`slice-graph.jsonl`), not nine indices, so one freshness gate, one query. Invariant-registry inlining ban (CI hard-fails any literal/predicate matching a registered invariant outside the spine). Positive-obligation control detection (a slice touching a tenant-scoped entity MUST declare+exercise tenant-scoping). Above-slice consistency tier (property test: every slice computing a tagged invariant yields the same value for fixed input). Clone detection is advisory-only.
- Consumer-driven contract tests run in the PRODUCER's CI (events are first-class blast edges generated from bus registrations). Spine anti-rot as blocking budgets (every spine symbol ≥2 importers; symbol-count ceiling; promotion-velocity vs demotion-velocity). Cohesion budget. Hard-fail any slice with >1 distinct handler.
- Context strategy. Harness computes+preloads the closure (one generated edge store); task card shows "closure = 14 files, ~31k tokens, p99 = 28 files." Sagas/money flows. AGENTS.md tells the agent up front context = union of participant contracts.

**Antipatterns**
- Applying "duplicate twice before extracting" to a business invariant. Pushing cross-cutting controls INTO the domain kernel (re-centralizes authz into the rot sink). Clone detection as the load-bearing fix (blind to the absent control). Agent setting/lowering its own blast-tier. Believing the import graph represents true coupling (the real graph is a slice mesh inside the bus). `cp -r` a sibling slice. Nine separate metadata artifacts. Treating a saga as just-another-slice with a higher tier.

## Axis 04. Hexagonal / Ports-and-Adapters Architecture
**Earn the seam.** A port earns its indirection only if, in the same PR, it proves ONE of. (1) multiple-participant variance, i.e. ≥2 live prod implementations with divergent semantics today (Postgres AND Dynamo; Stripe AND Adyen), or a dated/ticketed commitment within the planning horizon (a test double does NOT count); or (2) a real uncrossable boundary from a closed enum {clock, network-io, randomness, external-paid-service, db-transaction}. Else the port is forbidden by a creation-time CI gate. Inject a stub at the constructor (plain DI). This kills ~80% of the indirection.

**Prefer deep modules.** A module earns its existence by hiding more than it exposes. Deletion test. Imagine deleting the module and inlining it into its callers. If complexity vanishes, it was a pass-through and should go. If the same logic reappears across those callers, it earned its keep. This is the earn-the-seam gate above applied to any module, not just a port.

**Core principles**
- Earn the seam. Single-impl, zero-swap ports are forbidden at creation and auto-flagged for collapse if they slip through (90 days, impl_count==1 AND swap_events==0).
- Shape is not semantics, the headline safety invariant. The type system proves method shapes, nothing about auth applied / txn held / data durable / fail-closed / ordering. The port's CONTRACT SUITE is the definition of its contract.
- The port seam is simultaneously a trust, transaction, and durability boundary, none type-enforced. Every port carries machine-readable semantic tags (`@Trust`, `@Durability`, `@Atomic`, `@FailClosed`) the agent and CI read and the add/swap procedure branches on.
- Rich domain or no hexagon. An anemic context (logic in services, entities are getter/setter bags) collapses to a transaction-script/active-record slice. Heterogeneous architecture per context is correct.
- One model until the shape diverges. Pass the wire type inward for thin CRUD; introduce a domain type only on a real invariant. Where a mapper is needed, omission must be a compile error (exhaustive deconstruction).
- Derive-at-use, never read-stale. No checked-in topology files. The agent regenerates the port/wiring map against its OWN working tree as step 0 (sub-second, same AST pass as the import-linter, real DI container per profile). Dynamic bindings marked `<DYNAMIC: candidates, predicate verbatim>`, never a static guess.
- Fail closed at the root. A real-container startup self-test per profile fails the build on misbinding, fakes-in-prod, or fail-open-where-fail-closed.
- The enforcement layer is the trust root, so treat it as attack surface (arch-rules, contract tests, fakes, lockfiles under CODEOWNERS).

**Conventions & guardrails**
- Step 0 is always regenerate. Run `agent map <port>` against the working tree (includes in-progress edits) before reasoning about topology. A map whose generation SHA ≠ HEAD is refused.
- Route by the domain question, not the ring. "does this touch a business invariant?" YES → a domain method/constructor in `/domain`; NO (format/transport/persistence/wiring) → adapter/port work, domain unchanged.
- Change-shape before destination. A change altering the shape crossing a seam yields a ROUTED SET (`agent map` emits the full vertical worklist: domain + every adapter + inbound DTO + root); a green local fake is NEVER the stop signal for a multi-ring change.
- Trust the import set, not the path (location is a hint; never imitate a `/domain` file not confirmed import-clean). Never report a stateful swap as reversible. The only legal path is dual-write → shadow-read-compare → cutover. A passing core test with fakes proves the core, not the mapper/adapter; require the round-trip property test against the REAL datastore.
- Earn-the-port creation gate (the spine). Fail-closed composition-root self-test (highest-leverage single mechanism: exactly-one-binding; no *Fake in prod; `@FailClosed` resolves fail-closed; `@UntrustedInput` resolves through an adapter supplying AuthContext; `@Shared` = exactly one instance). Contract suite run against EVERY real adapter on EVERY merge; mutation-test the contract against the real adapter (a no-op mutant that still passes = the test asserts nothing).
- Control policy on the driving port. AuthContext mandatory on every `@UntrustedInput` method; input types are parse-don't-validate VOs. Exhaustive-by-construction mappers + one round-trip property test per aggregate. Type-leak check. Domain entities crossing a port boundary are forbidden. Enforcement-layer integrity under CODEOWNERS; assertion-ids snapshotted in a committed lockfile.
- Context strategy. Working set bounded by the earn-the-seam discipline (fewer seams = fewer hops). `agent map <port|use-case>` runs sub-second as step 0, returns impls (validated by set-equality vs the compiler's resolved implementor set), resolved port→adapter binding per profile (DYNAMIC markers), consumer graph, and the use-case-keyed change-fanout worklist. ONE regeneration command, not twelve cold-read JSONs.

**Antipatterns**
- Defaulting every service to the full hexagon. The speculative single-impl port. "Compiler proves conformance" ⇒ "swap is safe." Three-model trinity for field-isomorphic data. ISP-shredding a repository into LoadPort+SavePort (destroys the aggregate txn boundary). The god composition root. The checked-in generated manifest (lies on dynamic bindings, stale mid-edit). Curing ceremony with more ceremony. Naming-as-index (suffixes over the AST). The hollow contract test. Control-in-the-adapter by convention. Calling a stateful swap "one-line reversible."

## Axis 05. Event-Driven Architecture
**Earn the async.** Default synchronous + transactional (it hands the agent blast radius, F12, stack-trace-as-causal-chain, ACID, a type-checked contract for free). An event earns its async legibility cost only by proving ONE of. (a) temporal decoupling, (b) organizational/open-ended fan-out, (c) measured throughput a sync call can't meet, (d) durable-log-as-product. "Might scale someday" / "decoupling is nice" are REJECTED. Disqualifier. If every consumer is in the same repo+deploy unit and one synchronously needs another's answer, it is request/response in an event costume. Irreversibility override. PII or externally-irreversible side effects (charge/ship/email) do NOT earn async by decoupling alone. Choreography is legible ONLY for pure fan-OUT; the instant a handler conditions on ≥2 trigger events (distributed AND-join) or needs compensation, it MUST become a named orchestrated saga. Fan-in, not hop-depth, is the gate.

**Core principles**
- Grant-derived truth, runtime-primary. Topology is NOT discovered from repo scans (a liar the moment routing is content-based/wildcard/cross-account). The broker ACL grant list is the source of truth (an unlisted reader cannot connect); the 30-day OBSERVED fan-out graph is the PRIMARY map; checked-in declarations are a HYPOTHESIS CI continuously falsifies. An observed-but-undeclared edge fails the build.
- Blindness must be louder than partial knowledge. A 90%-accurate map is more dangerous than none. Every `blast_radius()` carries a COVERAGE verdict {complete|partial|unbounded}; any wildcard subscriber/content filter/cross-account egress forces PARTIAL, which escalates to a human like "unbounded."
- Safety properties are wiring edges, not code to audit. An agent can't prove a negative over handler internals. Relocate every safety property to a binding verified by PRESENCE. Idempotency = "registered through the dedup middleware?"; PII safety = "field tagged + reference-not-payload?". This is the master template.
- Key everything on (eventName, schemaVersion), derived from the deserializer. The question is "who consumes the VERSION I'm about to emit, and which BACKWARD-compat readers silently drop my new field." FULL compat + explicit semantic gating is the floor; BACKWARD is the trap.
- Immutable events are a permanent data-residency decision, not a schema edit. Corrections are additive only. PII in an immutable log + right-to-erasure = two-phase erasure (crypto-shred the key AND purge every downstream plaintext projection).
- Convert absence into a positive signal. Set-difference trace oracle, liveness annotation, FlowStalled deadline events, projection_gaps flags.
- Runtime is the safety boundary, CI is a proxy. Idempotency-correctness, lag, replay-currency are NOT decidable at merge time; a green gate the agent reads as a safety certificate is worse than none; the continuous PRODUCTION invariant checker is the real proof.
- Price legibility in tokens, triage the scaffolding. The legibility layer is itself a stateful distributed system that rots faster than the code; ship a tiered read interface; build the load-bearing-for-correctness slice first.

**Conventions & guardrails**
- Before editing any event schema, read the version-matrix (tier-2), not the summary. CI must already surface "producer at v3, analytics at v1, fields {x} dropped silently."
- Before touching a slice that EMITS topic T, read `reverse-fanout.json` (harness injects it). The producer's manifest does NOT list its consumers, so never grep/guess. If coverage=PARTIAL or any wildcard could match, STOP and escalate.
- Never hand-write dedup logic. Register the handler THROUGH the dedup middleware factory and declare its `duplicateSources` {redelivery|upstream-retry|replay|cdc-replay}. For outbox-sourced topics, dedup on (topic, outbox_seq) NOT messageId (CDC is a second at-least-once hop; messageId rotates).
- When a handler becomes "if I've now seen A AND B, do C", STOP; promote to a named saga under `process/` with explicit timeout + compensation.
- Adding a PII field to an immutable event is a permanent multi-replica data-residency decision; default reference-not-payload. For any field whose absence differs from its zero value, use presence-tracking (proto has-bit / Avro union sentinel) + an upcaster, never a business default (it fabricates counterfeit history on replay).
- Debug by `root_correlation_id` (the WHOLE saga forest), not `correlation_id`. Read `liveness.json` BEFORE topology. Run the trace as a SET DIFFERENCE, so the answer is the NOT-OBSERVED list. A `saga_instances` row is a concurrently-mutated racing object. Read its version twice ~1s apart; if changed, report "in motion." Replay/DLQ-drain are PRIVILEGED, default DRY-RUN, version-aware (idempotent replay can still apply a STALE effect).
- Gates. `earn-it.gate` (rejects async/choreography without a named justification); deny-by-default consume AUTHZ (broker provisioned from `topic-acls/` via GitOps; PII topics need code-owner signature on consumer addition); `dedup-binding.lint` + duplicate-source contract test; `semantic-compat.gate` (unit/enum-hash/invariant/fill-rate change = BREAKING); `pii.gate`; `observed-vs-declared.gate` + `consumers.lock`. Poison policy = HALT-the-projector by default (advancing the checkpoint past a skipped event makes `last_applied_position` LIE). DLQ-monitor + drain-lag alarms + synthetic per-critical-topic canary. `replay-rebuild.test` + saga adversarial harness + continuous production invariant checker. `FlowStalled` deadline events keyed on correlation_id.
- Context strategy. Reconstruct an async flow in 5 bounded steps. (0) `catalog.summary.json` tier-0; (1) `reverse-fanout.json` for the emit-topic (the re-manufactured F12, pushed to the edit site; a CLOSED SET from the grant list); (2) follow `causation_ids[]` (no zero-arg emit, so context can't be dropped); (3) cross saga boundaries by root via `saga-forest-index`; (4) `liveness.json` + set-difference trace. Tiered read interface; the set-difference oracle points at the one WEDGED branch when the forest exceeds the window.

**Antipatterns**
- Generating topology from STATIC repo scans. A mandatory producer-assigned idempotencyKey in every schema. Keying the catalog on event NAME alone. BACKWARD compat as the "sane default" (its job is to make breaks silent). Adding an optional default to a replayed event. A stable customer id in the idempotency key (cross-topic re-identification token in the forever-log). Crypto-shredding as the COMPLETE erasure answer. DLQ-skip-and-advance as default poison policy. DLQ-replay as "safe because idempotent" (doesn't defend against STALE effects). The ">3 hops → saga" canary (gate on fan-IN, not depth). Reading a `saga_instances` row as an atomic snapshot. A single-threaded test as a "proof" of compensation composition. Treating the legibility scaffolding as N co-equal artifacts.

## Axis 06. Serverless / Function-as-a-Service
**Verdict. "Event-Earned Serverless: Modular-Monolith-by-Default" (the program's first unanimous verdict).** DEFAULT = modular monolith (one runnable process, IAM principals at the service edge, a greppable in-process call graph) for request/response CRUD-over-a-database with steady traffic. If you must build a second distributed system just to let an agent see what the program does, you have already failed the agent-legibility lens. LAMBDALITH (one function per bounded context, internal router, one role, one concurrency reservation) is the explicit middle for serverless billing/ops on a request/response app you can tolerate cold starts on (`sam local start-api` restores the single runnable process). FINE-GRAINED FaaS earns its cost only when the workload is natively event-shaped AND bursty/idle (object-store pipelines, queue/stream consumers, scheduled jobs), the trigger-binding IS the application, and at-least-once idempotency is needed anyway. The deciding axis. Is the agent's verification loop allowed to require live cloud creds every iteration, and is the workload genuinely event-shaped?

**Core principles**
- Falsifiable facts over presence/intent (the first law). A green check is a claim an adversarial optimizer produced. Decorator-present, free-text-justification, and lint-count-zero are gameable and worse than nothing, they manufacture a false provenance trail the next agent trusts.
- Deployed-effective truth is authoritative; source/synth is a fast-but-fallible index. Effective permission = role ∩ boundary ∩ SCP ∩ resource-policy − deny; three of five inputs live above the repo. The authoritative IAM line comes from `simulate-principal-policy` against the LIVE role + CloudTrail observed-use, never the role JSON.
- Detection ≠ containment. Test a control by "does it cap the loss when the agent ships the problem anyway." The circuit breaker (reservedConcurrency cap + finite maxReceiveCount + DLQ) bounds the dollar loss regardless of whether a detection gate was gamed.
- The blast-radius unit is the account concurrency pool (default 1000, shared across stacks/teams), not the function. Reserving for A subtracts from the unreserved floor for B/C; this lives in an account-level ledger.
- Generate the policy, don't let the agent author it. Least-privilege must be the CHEAP path to green. Derive from the bundler module-graph SDK-call set; forbid hand-written role statements. The agent structurally cannot widen the role.
- Granularity is derived from the permission graph. A deployable's boundary = a coherent least-privilege grant set; blast-radius divergence is the split signal.
- Local-green is necessary, never sufficient. The cheapest loop signal lies on exactly the serverless axes (IAM, redelivery, ordering, cold-start). The verdict must be multi-tier and machine-readable so an unproven dimension reads RED.
- Minimize deployable units first, instrument what remains second.

**Conventions & guardrails**
- To change a behavior. Load `AGENTS.md` decision record → the unit's `docs/generated/<fn>.contract.json` (trigger + effective-IAM + backing-resources + idempotency) → handler + its `lib/` module graph. Never reason from handler source alone (half the program is in `infra/template.yaml`).
- NEVER hand-edit `iam.generated.json`. To grant a permission, add the SDK call and re-synth (hand-written role statements = lint failure).
- To split a function out, produce a FALSIFIABLE artifact (CloudWatch metric, load-test result, a parent-role denylist action the child isolates with CI diffing the two roles, a different timeout/memory tier, a declared sub-Xms p99 SLO, or a real non-Lambda event-source mapping in the same diff). No artifact → the handler auto-folds back into the parent router. Splits happen retroactively from telemetry, never at creation.
- Idempotency is proven by the redelivery contract test (invoke twice with identical payload → exactly one side effect), NOT a decorator. Never key dedup on messageId/receiptHandle/timestamp/random; derive from the business payload.
- Read local-green as "verified: logic-only." The verdict {tier1_logic, iam_validated, redelivery_tested, tier4_authz} must be all-green before merge. IAM verified against an ephemeral per-PR stack or Access Analyzer simulate, NEVER LocalStack (does not enforce IAM).
- Any PR touching function code AND a stateful resource is forward-only unless it proves backward compatibility (expand-contract); record `rollback-safe-to: vN` (rollback is partial). Classify a deploy plan on the attribute-level behavior-diff denylist, NOT CloudFormation Modify-vs-Replace.
- Gates. GATE ZERO hermetic synth (synth twice with `--no-lookups` + frozen lockfile + fixed clock; fail if outputs differ; until it passes, every derived map is UNVERIFIABLE). Generated least-privilege IAM with 3-state coverage (covered/uncovered/UNVERIFIABLE-fails); ban partial wildcards (`Put*`, `*Item`, `:*`, `/*`) and `*FullAccess` ARNs; effective-permission reconciliation via simulate-principal-policy; CloudTrail observed-use ratchet auto-opens PRs removing unused grants. Privilege-escalation reachability gate (HIGH, above the wildcard gate). Denylist `iam:PassRole`/`sts:AssumeRole`/`lambda:Update*`/`iam:Create*PolicyVersion`. Inbound boundary. Require `aws:SourceArn` AND `aws:SourceAccount` on every service-principal grant. Trigger-graph cycle detector over the synthesized template. Default-deny unbounded concurrency. Finite reservedConcurrency on every non-HTTP function + a runtime alarm whose ACTION sets reserved concurrency to 0. Hard DLQ + finite maxReceiveCount + ReportBatchItemFailures. Account-concurrency ledger + amplification-aware cost model (worst-case = base × Π(per-trigger amplifiers); runaway signal is VOLUME, not latency).
- Context strategy. Reconstruct a behavior's closure from exactly four things. (1) the per-fn `contract.json` fragment (trigger + simulated effective-IAM + backing-resource ARNs + idempotency + initMs/bundleKB + rollback floor); (2) the handler + its `lib/` module graph; (3) the relevant trigger-graph slice; (4) the account `concurrency-budget.yaml` row. Maps sharded per function (never a committed global render, i.e. a merge-conflict factory). Per-task token bill is itself a granularity signal. If loading one closure exceeds budget, the function is too entangled; consolidate toward the lambdalith. Three states everywhere truth is uncomputable from the repo. Covered/uncovered/UNVERIFIABLE (UNVERIFIABLE forces a WARN, not a false green).

**Antipatterns**
- Building serverless to avoid managing servers for a steady CRUD app. Wildcard IAM and its disguised cousins (partial wildcards, `*FullAccess` ARNs, the nag-suppression one-liner). Hand-authoring/widening the execution role (every iteration toward green only adds grants). Treating the per-function role as "the threat model" while ignoring escalation reachability (a scoped `iam:PassRole` is admin). Reasoning only about the outbound role, never who can INVOKE the function (missing `aws:SourceArn`/`SourceAccount` = confused-deputy). S3-write-back-to-trigger-bucket / stream-writes-own-table cycles. N+1 fan-out (SDK invoke/PutEvents inside a per-item loop). Idempotency-by-presence. Trusting local-green / sam-local-200 / a clean changeset as prod-truth. Committing global rendered maps and gating on stale-diff. Believing "one-call rollback" is total (pins code+config, not migrated schema/rotated secret/changed event shape).
